# DM security invariants

Scope: upgraded clients sharing durable IndexedDB. SI-06 through SI-10 bind messaging keys to the explicitly requested Schnorr account key. They do not authenticate display names, prove current global device membership, or establish Signal conformance.

| Rule | Implementation | Regression evidence |
| --- | --- | --- |
| SI-01 Atomic state consumption: a sending-chain position has at most one successful consumer. | `signalProtocol.ts` encrypt/decrypt; `storageService.ts` compareAndSwapMetadata. Failed speculative computations cannot return an envelope. IDB snapshots are compared and committed in one transaction; volatile storage fails closed. | `ratchetSecurity.test.ts`: X/Y, 64 independent consumers, send/decrypt overlap, reopened DB; `deliverySecurity.test.ts`: 32 ChatService sends plus flush. |
| SI-02 Authentication before commit: cryptographically unauthenticated input cannot mutate durable crypto state. | Tentative receiver bootstrap; joint session/OPK/accepted-row transaction. ChatService receive discovery does not persist bundles; failed decrypt neither deletes sessions nor stores tombstones/seen IDs. | `bootstrapSecurity.test.ts`: repeated forgery, complete-store snapshots, cold cache, accepted-row write failure, legitimate recovery. |
| SI-03 Immutable retransmission: retries reuse the originally produced encrypted envelope. | `signal-envelope:<sender>:<recipient>:<messageId>` journal commits alongside sending state. ChatService adopts existing cached envelopes and refuses invalid ones; stale row writes cannot erase ciphertext/evidence. | `ratchetSecurity.test.ts`: logical retries/restart/content change; `deliverySecurity.test.ts`: stale retries, send/flush, stale snapshots. |
| SI-04 Media confidentiality equivalence: media receives at least the same confidentiality boundary as DM text. | All active ChatView picker branches call ChatService.sendFile -> chatMediaService.encryptAndUpload. | SI-06 Signer-to-subject binding: a valid signature is insufficient unless its signer is authorized for the claimed subject. | `dmIdentity.ts` verifyBinding/verifyAuthenticatedBundle verify Schnorr against the requested account ID; ChatService validates cached, REST and Gun candidates. | `identityPrekeySecurity.test.ts`: valid first binding, Mallory/wrong account signer, wrong device and malformed binding; `identityPrekeyIntegration.test.ts`: REST/Gun substitution, wrong local signer. |

Paths above are under `src/services/` and `unit_tests/`. See [DM delivery v1](DM_DELIVERY_V1.md) for status semantics and compatibility.

Limits: reload all clients sharing IndexedDB; old blind writers can bypass CAS. Wire v4 is required for the authenticated path. Legacy records and envelopes remain preserved but untrusted/quarantined; no silent upgrade or downgrade. SI-02 covers bootstrap/decrypt authentication failures, not the excluded F06 reset controls. F06 epochs/reset/replay authority and prior-chain skipped-key behavior remain unresolved. Relay availability is not an authenticated reservation service: stale public OPKs may be offered, but cannot obtain a second successful receiver consumer. Historical plaintext media, dormant WebRTC transfers, local key/plaintext compromise, whole-database rollback and transport availability remain outside these guarantees. See [identity/prekey contract](DM_IDENTITY_PREKEY_V1.md).

## Session epochs (F06, wire v5)

- **SI-11 Replay across epochs:** accepted bootstrap authority cannot regain control in a later generation. `dmSessionEpoch.admitEpoch`, `SignalSession.decrypt`; `sessionEpochSecurity.test.ts`: stale signed reset, old-generation authorized certificate, retired simultaneous branch.
- **SI-12 Reset authority:** only an authorized device-signed successor naming the current parent and generation+1 can replace it; local proposals require current-session peer confirmation. `SignalSession.resetSession/encrypt`, `dmSessionEpoch.admitEpoch`, `ChatService.handleWsMessage`; tests: relay controls, provisional reset rejection, signed newer reset, forged reset/no state drift.
- **SI-13 Persistent replay resistance:** accepted IDs and candidate history share the crypto CAS and have no timed expiry. `dmSessionEpoch.readEpoch/epochChange`, `SignalSession.decrypt`; tests: restart replay, duplicate reset after reopen, ratchet loss and valid parent-bound recovery.
- **SI-14 Deterministic simultaneous initiation:** opposite same-parent candidates select the lexicographically smaller authenticated account initiator; losing branches are receive-only until the next generation. `dmSessionEpoch.admitEpoch`, `SignalSession.encrypt/decrypt`; tests: both initial arrival orders, simultaneous resets, losing in-flight traffic, retired branch rejection.

These rules supersede the earlier F06 exclusions for v5 only. v3/v4 state remains quarantined; no historical epoch migration is inferred. Whole-storage rollback/erasure and unavailable transport are outside these persistence/liveness guarantees. Contract: `DM_SESSION_EPOCH_V1.md`.

## Receive retention and acceptance (F08/F09)

- **SI-15 Skipped-key retention:** receive DH changes preserve keys within MAX_SKIP/MAX_TOTAL_SKIPPED and the four-transition window. `signalProtocol.skipMessageKeys/retainSkipped/ratchetStep`; `receiveStateSecurity.test.ts`: previous-chain A1, gap boundaries, total eviction, last retained transition, restart.
- **SI-16 Authentication-before-skipped-key-consumption:** skipped consumption/expiry commits only after AEAD and the receive transaction succeed. `signalProtocol.ratchetDecrypt`, `SignalSession.decrypt`; tests: forged skipped-key first, corrected ciphertext, failed durable acceptance.
- **SI-17 Acceptance-aware deduplication:** observation is not accepted history. `ChatService.receiveRemote/receiveImpl`, `dmReceiveState.receiveCommitChanges`; tests: concurrent exact duplicates, outer-ID collision, changed mutable metadata, Gun duplicate notifications.
- **SI-18 Retryability preservation:** prerequisites/storage failure yield retryable state, not accepted tombstones. `ChatService.decryptFrom/retryPendingReceives`, `SignalSession.decrypt`; tests: before-bootstrap automatic/manual retry, bundle unavailable/reopen, failed DB acceptance.
- **SI-19 Atomic receive acceptance:** ratchet, skipped consumption, epoch/OPKs, accepted row, position ledger and inbox removal share StorageService CAS. `SignalSession.decrypt`, `dmReceiveState.receiveCommitChanges`, existing `StorageService.compareAndSwapMetadata`; tests: abort after metadata writes, concurrent acceptance, duplicate replay after reopen.
- **SI-20 Bounded pending state:** 64 candidates and 2 MiB/account, 256 KiB/envelope, first-observation TTL 24h; 64 active receives/ChatService. `dmReceiveState.enqueuePending/pendingEntries`, `ChatService.receiveRemote`; tests: count/byte/expiry bounds, duplicate lifetime, bounded admission.

Contract: `DM_RECEIVE_STATE_V1.md`. Accepted conversation/epoch history is not covered by the unaccepted-inbox size bound. Transport suppression, queue saturation/eviction, whole-DB rollback and unknown account/device authority remain separate limitations.
