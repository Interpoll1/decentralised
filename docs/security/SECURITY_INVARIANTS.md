# DM security invariants

Scope: upgraded clients sharing durable IndexedDB. These rules do not establish account identity authentication or Signal conformance.

| Rule | Implementation | Regression evidence |
| --- | --- | --- |
| SI-01 Atomic state consumption: a sending-chain position has at most one successful consumer. | `signalProtocol.ts` encrypt/decrypt; `storageService.ts` compareAndSwapMetadata. Failed speculative computations cannot return an envelope. IDB snapshots are compared and committed in one transaction; volatile storage fails closed. | `ratchetSecurity.test.ts`: X/Y, 64 independent consumers, send/decrypt overlap, reopened DB; `deliverySecurity.test.ts`: 32 ChatService sends plus flush. |
| SI-02 Authentication before commit: cryptographically unauthenticated input cannot mutate durable crypto state. | Tentative receiver bootstrap; joint session/OPK/accepted-row transaction. ChatService receive discovery does not persist bundles; failed decrypt neither deletes sessions nor stores tombstones/seen IDs. | `bootstrapSecurity.test.ts`: repeated forgery, complete-store snapshots, cold cache, accepted-row write failure, legitimate recovery. |
| SI-03 Immutable retransmission: retries reuse the originally produced encrypted envelope. | `signal-envelope:<sender>:<recipient>:<messageId>` journal commits alongside sending state. ChatService adopts existing cached envelopes and refuses invalid ones; stale row writes cannot erase ciphertext/evidence. | `ratchetSecurity.test.ts`: logical retries/restart/content change; `deliverySecurity.test.ts`: stale retries, send/flush, stale snapshots. |
| SI-04 Media confidentiality equivalence: media receives at least the same confidentiality boundary as DM text. | All active ChatView picker branches call ChatService.sendFile -> chatMediaService.encryptAndUpload. Fresh AES-256-GCM key/IV; version/context/name/type/length authenticated as AAD; descriptor only inside DM ciphertext. | `mediaSecurity.test.ts`: 17 B, 400 KiB +/- 1 B, 3 MiB; captured upload, exact recovery, wrong key, altered ciphertext/metadata; actual DM and reopened history. |
| SI-05 Evidence-bounded status: a status cannot imply evidence the implementation did not obtain. | `dmDelivery.ts`; ChatService.processAccepted/deliver. DM `confirmed` requires a decrypted peer receipt naming the exact envelope digest; relay ACK and Gun local ACK cannot confirm. Restart projects durably accepted receipts. | `deliverySecurity.test.ts`: no WS/Gun failure, local ACK, relay timeout/late ACK, valid/wrong receipt, duplicate receipt, interrupted projection. |

Paths above are under `src/services/` and `unit_tests/`. See [DM delivery v1](DM_DELIVERY_V1.md) for status semantics and compatibility.

Limits: all clients writing this database must be upgraded/reloaded. CAS cannot constrain an old client that blindly overwrites state. Existing session/wire v3 cryptography is retained; F01/F06/F07 and previous-chain skipped-key behavior are outside this change. Historical plaintext media cannot be retroactively encrypted. Dormant WebRTC file-transfer code is unchanged and is not covered by SI-04; enabling it requires its own authenticated media design. Local key/plaintext compromise, rollback of the entire database, transport availability, and account-to-device authorization remain outside these established properties.
